# Build & deploy

## Build

With the venv activated (see [develop-and-test.md](develop-and-test.md)):

```
npm run build
```

1. `build:js` — webpack builds `dash_echarts/dash_echarts.min.js` and
   `dash_echarts/async-DashECharts.js` (see [architecture.md](architecture.md)).
2. `build:backends` — `dash-generate-components` regenerates the Python class from
   `src/lib/components/DashECharts.react.js`.

Commit the regenerated files in `dash_echarts/` with the source changes: apps install
the package from git, without building it.

## Release

1. Update the version in `package.json` (`"version": "x.y.z"`).
2. Run `npm run build`: it copies the version to `dash_echarts/package-info.json`,
   which gives `dash_echarts.__version__`.
3. Add the changes to `CHANGELOG.md`.
4. Commit, tag and push (tags have no `v` prefix):

   ```
   git tag x.y.z
   git push origin main --tags
   ```

## Install in an app

```
pip install git+https://github.com/Covarians/dash_echarts.git@x.y.z
```

or in the app's `requirements.txt`:

```
dash_echarts @ git+https://github.com/Covarians/dash_echarts.git@x.y.z
```

## Dash version

The Python class is generated by the Dash version of the build environment,
pinned in `requirements.txt` to the version the apps run (Dash 2.18.2, with
`setuptools<81` which Dash 2.x needs). When the apps move to a newer Dash, update
this pin and rebuild.
