# Architecture

## Source layout

```
src/
├── lib/
│   ├── index.js                     # exports DashECharts (entry of the Dash bundle)
│   ├── LazyLoader.js                # React.lazy import of the implementation
│   ├── components/
│   │   └── DashECharts.react.js     # thin wrapper: propTypes, defaults, Suspense
│   └── fragments/
│       └── DashECharts.react.js     # the implementation (ECharts and extensions)
└── demo/                            # browser sandbox (see develop-and-test.md)
    ├── index.js
    └── App.js
dash_echarts/                        # Python package (mostly generated, see below)
usage.py                             # small Dash example app
```

## Why two component files

The component is split so the heavy chart code is only downloaded when a chart is displayed:

- **`components/DashECharts.react.js`** is small. It declares the props
  (`propTypes` and default values) and renders the implementation inside a React
  `Suspense`, with an empty box of the same `id` and `style` while it loads.
  `dash-generate-components` reads **this** file to generate the Python class.
- **`fragments/DashECharts.react.js`** is the real component: it creates the ECharts
  instance, applies the option and the `fun_*` props, registers the events and
  disposes the chart on unmount. It imports ECharts, `echarts-gl`, `echarts-stat`,
  the bmap extension and `mapbox-gl`.

Change props in **both** places: their declaration in the wrapper, their use in the implementation.

## Build output and loading

`npm run build` produces, in `dash_echarts/`:

| File | Content | Loaded |
| --- | --- | --- |
| `dash_echarts.min.js` | the wrapper (a few KB) | on every page of an app that imports `dash_echarts` |
| `async-DashECharts.js` | the implementation and the ECharts libraries (~3 MB) | only when a chart is displayed |
| `*.map`, `*.LICENSE.txt` | source maps, third-party license notices | — |

Dash serves these files from `/_dash-component-suites/dash_echarts/`. The
`@plotly/webpack-dash-dynamic-import` plugin makes the main bundle fetch the async
file from the same location. The list of async files is declared in
`dash_echarts/__init__.py` (`async_resources`): it must match the
`webpackChunkName` in `LazyLoader.js`.

React, ReactDOM and prop-types are **not** bundled (webpack `externals`): the
component uses the React provided by Dash (React 16.14 with Dash 2.x by default,
React 18 with recent Dash). The `react` dev dependency is only used by the sandbox.

## Python package

| File | Origin |
| --- | --- |
| `DashECharts.py`, `_imports_.py`, `metadata.json` | generated by `dash-generate-components` |
| `package-info.json` | copy of `package.json`, made by the build |
| `__init__.py` | hand-written: declares the JS files Dash serves |
| `*.js`, `*.map`, `*.LICENSE.txt` | built by webpack |

The Python code is generated by the Dash version installed in the build
environment (`requirements.txt`). Keep it equal to the Dash version the apps run.
